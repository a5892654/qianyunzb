# 语音模型切换与皮套帧率

## 在有参考音频的设备上使用

1. 更新软件源代码并重启。
2. 打开【语音设置】，保留原来的【克隆参考音频】。也可使用【浏览…】选择音频的完整路径。
3. 模型大小选择 **0.6B**，点击【切换模型】。需要更大模型时同样可切回 **1.7B**。
4. 等待状态从“正在切换”变为实际运行的模型名称，再试听。首次使用会下载模型，后续复用本机缓存。

切换会同时更新流式语音和 ComfyUI 后端的模型选择。正在播报时拒绝切换，避免截断当前语音；切换期间后续语音等待，新模型就绪后恢复。软件只停止自己启动的旧引擎；外部引擎的模型不匹配或身份未知时会明确提示，不会显示为切换成功。

【关闭引擎】现在也会停止本软件启动的流式语音服务，释放其 CUDA 模型。界面在新服务支持时显示 PyTorch 模型预留显存，此数字不包含整台电脑或所有 GPU 进程。

参考音频在其他设备上时，本机可以保存选择，但无法核对原音色效果。不要把系统测试音频的结果当作用户原音色的试听。

本机真实 0.6B 流式验证使用 Windows 系统测试音频：预热后两次首包分别约 0.20 秒、0.25 秒，生成约 5.2 秒和 4.56 秒音频；模型加载与预热约 24 秒。测试后 PyTorch 已分配约 2250 MiB、预留约 2448 MiB（2.39 GiB），不包含 CUDA 上下文、驱动及其他进程，不能当作整机显存占用。此结果不代表另一台设备的延迟或原音色质量。

## 语音运行环境

已有有效的 `tts.ttsd_python`、`tts.ttsd_script` 会继续使用；配置路径不存在时，软件尝试项目内 `.tts-venv/Scripts/python.exe` 与 `tools/tts_server.py`。

新设备需要单独安装 CUDA PyTorch 和语音依赖，不要跨机器直接复制虚拟环境。建立 `.tts-venv` 后，在该环境安装与显卡驱动匹配的 CUDA PyTorch，再执行：

```powershell
.tts-venv\Scripts\python.exe -m pip install -r requirements-tts.txt
```

依赖固定为 `faster-qwen3-tts==0.5.4`、`transformers==5.15.1`。真实加载验证发现 Transformers 5.18 与当前语音库的 MimiConfig 不兼容，因此语音环境独立锁定版本，不修改 ComfyUI 环境。模型缓存位于 `models/tts/`，未纳入 Git。

## 皮套卡顿修复

原链路每帧通过 CDP 读取 PNG，还依赖浏览器 RAF 推进模型。新链路由合成器的帧请求推进一次动画并绘制一次，通过本机 WebSocket 传输原始 RGBA，去掉 PNG、Base64 和逐帧 CDP JSON。保留透明度、原模型贴图和取景；PNG 调试入口仍可用。

渲染循环关闭独立 RAF，防止重复绘制；后台窗口禁用浏览器降速，读取按绝对截止时间调度。在【一键开播】状态中分别显示游戏更新率、源画面处理率、皮套实际更新率和读取耗时，避免把重复合成误当作皮套在更新。

同一台机器、同一份真实皮套、720×720 皮套输出的本机测量：原链路约 **26 帧/秒**，新链路独立测量约 **30 帧/秒**（4 秒观测到 120 张不同画面）。这不是另一台设备或直播平台的保证值；当前源画面仍以 30 帧/秒输出。

复现：

```powershell
.venv\Scripts\python.exe tools\benchmark_live2d_motion.py outputs/avatar_benchmark.json
.venv\Scripts\python.exe tools\verify_tts_models.py
```
